# HW52 · Planova

Курсовой frontend-проект: управление проектами и задачами на React и Redux Toolkit.

## Возможности

Создание и настройка проектов; создание, просмотр, изменение и удаление задач; Kanban-колонки «К выполнению», «В работе», «Готово»; изменение статуса на карточке; приоритеты, сроки, теги; поиск и комбинированные фильтры; сортировка; аналитика по проектам; экспорт JSON; сброс демоданных с подтверждением. Удаление проекта согласованно удаляет его задачи. Пустые состояния, ошибки, загрузка и недоступность хранилища показываются явно.

В Redux находятся данные проектов/задач, статусы операций и фильтры. Черновики форм и открытые диалоги остаются локальным состоянием. Все операции с данными проходят через createAsyncThunk. Валидация и вычисления отделены от React; селекторы используют createSelector. Мутации демохранилища сериализованы, чтобы параллельные записи не теряли изменения.

## Данные и будущий сервер

По умолчанию работает деморежим: исходный JSON загружается через HTTP, изменения сохраняются в localStorage под hw52.workspace.v1. Это не имитация наличия сервера: индикатор режима сообщает, где хранятся данные. Серверная аутентификация, многопользовательская синхронизация и база данных в эту frontend-работу не входят.

Для подключения сервера скопируйте .env.example в .env.local и задайте VITE_API_URL, например http://localhost:3000/api. Перезапустите Vite. API-слой уже использует GET, POST, PATCH и DELETE, AbortSignal, таймаут, проверку HTTP-статуса и структуры ответа. [docs/API.md](docs/API.md) содержит точный контракт. Для Pages задайте одноимённую repository variable; в публичный frontend нельзя помещать секреты. Браузерные тесты принудительно используют деморежим и не изменяют ваш сервер.

## Архитектура

app — store; features/projects, features/tasks, features/filters — функциональные модули; features/workspace — загрузка; pages — страницы; widgets — компоновка; services/api — изолированный транспорт; shared — валидация, константы и Modal. Страницы загружаются через lazy/Suspense. HashRouter обеспечивает вложенные маршруты на статическом хостинге.

## Тема курсовой

Выбрана система управления задачами — одна из тем, предусмотренных заданием. Материалы не содержат индивидуального согласования темы с преподавателем; такое согласование не заявляется. При сдаче используйте фактическую тему, утверждённую на курсе.

## Запуск

Нужны Node.js 24 и npm. Откройте эту папку в VS Code (File → Open Folder) или выполните code . из её корня.

```bash
npm install
npm run dev -- --open
```

По умолчанию: http://127.0.0.1:5173/. Для параллельного запуска разных работ задайте разные порты, например npm run dev -- --port 5174 --open. Остановка — Ctrl+C. Live Server и открытие исходного index.html двойным щелчком не заменяют Vite.

```bash
npm run test:logic
npm test
npm run lint
npm run build
npm run preview -- --open
```

Production preview: http://127.0.0.1:4173/. Команда npm run check объединяет ESLint, Vitest и production-сборку. Дополнительные нативные тесты запускаются отдельно командой test:logic.

## Браузерные проверки и отчёт

```bash
npx playwright install chromium
npm run test:e2e
npm run test:report
```

Playwright сам собирает приложение с base=/repository-check/ и поднимает preview-сервер. Сценарии предусмотрены для настольного и мобильного размеров. Перед запуском освободите порт 4173. Отчёт Playwright: playwright-report/index.html.

Команда test:report **заново запускает настоящий Vitest** и сохраняет reports/vitest.json, reports/test-output.txt, reports/test-report.html и скриншот reports/tests.png. Старый JSON удаляется перед запуском; неуспешный запуск не выдаётся за успешный. В CI эти файлы доступны в артефакте test-evidence и после публикации — в /reports/ сайта.
